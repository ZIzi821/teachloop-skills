# 界面、视觉与中文文案

前半部分适用于采用此方法的教学产品；最后的小程序规范仅用于原项目。

## 学生与教师的信息层级

学生关键页面优先显示下一步行动，完成后给出明确衔接。今日学习、历史记录和设置分别承担作用，减少重复入口。额外统计或排行榜应能说明它帮助孩子做什么，再决定展示位置。

教师工作台先呈现待处理事项与常用操作。每条事项应能到达对应学生、任务、录音或证据，并在实际处理后解除。需要深入了解的统计放在相应详情中。

长页面按用户任务分区。切栏应保留必要上下文、处理深链定位，并检查切换后的图表和滚动。复杂算法指标先给可解释结论，统计口径按需展开。

## 中文文案

使用当前状态与可执行动作，围绕用户任务写句子。保留真实权限要求、学习档位与不可恢复操作的后果。

| 情境 | 推荐表达 |
| --- | --- |
| 等待教师 | 已提交，等待老师检查 |
| 未观察某能力 | 还没观察；下节课观察能否独立完成 |
| 没有课程 | 上完课后，这里显示课程记录 |
| 网络失败 | 网络不稳定，请稍后重试 |
| 有效练习不足 | 继续积累复习记录，再查看调整建议 |
| 参数建议 | 当前复习可能偏密；老师可结合课堂表现决定是否应用 |

减少反复说明“只是、不会、仅供”的防御性文案；将必要事实写成用途和动作。避免在儿童界面展示数据库错误、内部服务名或参数细节。开发交付报告可以保留准确技术信息。

## 可读性和真实状态

任务文字保留教师输入的换行，支持长内容展开。检查大字号、较长姓名、按钮换行、滚动和底栏遮挡。视觉颜色帮助辨认状态，同时提供文字含义。

加载、空数据与失败分别处理。读取失败不能用示例课程或上一身份数据充当成功；预览和测试可使用明确的合成数据。保存失败保留恢复路径，不提前显示成功。

音频体验需要确认真实播放进度，提供预载、超时和有限回退。示范结束与开始录音的衔接以实际状态推进，避免加载卡住时提前开麦。生成了音频文件、填写了映射、上传云端和设备实际播放是不同证据。

## 当前微信小程序的视觉适配

以下是 2026-11-12 从本地源码核实的实现规范。改动时重新查看拥有它们的文件；其他产品选择自己的视觉系统。

- 颜色由 `miniprogram/app.wxss` 的 CSS 变量集中维护：暖白底、深青绿主色，其他语义色用于提示、错误与信息。
- 扁平背景与边框分组，当前样式验证器禁止阴影和渐变；复用现有 `ui-*` 行、分组、标签、分栏和按钮。
- 当前字号档位为 24/26/30/34/44/56rpx，圆角档位为 12/16/24/999rpx；细节和大型展示的例外以 `tools/validate-design-tokens.js` 为准。公共按钮最小高度为 96rpx。
- 学生底栏为学习、成就、日程；教师底栏为首页、待办、管理、日程。新增入口优先放入对应任务位置。
- 课程详情按记录、任务、资料、错题分栏；学生详情按概览、课程、计划、设置分栏。查看当前组件与页面后再扩展。
- 饼图与柱状图当前使用普通视图；仍使用 Canvas 的图表检查原生层级、底栏覆盖及切栏重绘。
- 颜色变更同时检查 JS/WXML 的 Canvas 色值、确认框与开关色值。

验证入口：`tools/validate-design-tokens.js`、`tools/validate-ui-copy.js`、`tools/validate-miniprogram-structure.js`。静态通过之后，交互、音频与层级问题还需微信开发者工具或对应设备证据。
