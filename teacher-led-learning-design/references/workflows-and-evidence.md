# 流程、状态与学习证据

用于作业、观察、计划、复习、激励及相关数据设计。具体字段和阈值读取目标项目当前实现。

## 角色与循环

| 角色 | 主要任务 | 界面需要回答的问题 |
| --- | --- | --- |
| 教师 | 定目标、备课、观察、布置、检查、调整 | 谁需要我处理，证据在哪里，下一次教什么？ |
| 学生 | 理解任务、练习、提交、重练 | 现在做什么，怎么做，完成后去哪？ |
| 家长 | 协助进入、理解安排和反馈 | 孩子现在需要哪种帮助，老师给了什么要求？ |
| 教师学生预览 | 体验同一学习页面与状态 | 孩子实际会看到什么，交互是否清楚？ |

家长不必成为独立账号类型；沿用目标项目的身份模型。教师预览保持教师身份，复用目标学生的真实页面与已有配置；合成学生适用于测试示例。

预览交互默认在本地会话演练，录音可以本地录制和回放，提交结果在预览状态中模拟；保留现有项目禁止上传录音和写入学生记录的契约。只有用户明确需要跨设备保存预览结果时，才设计额外隔离存储及清理机制，不默认新增后端会话或上传服务。

## 证据含义

| 记录 | 可以支持的判断 | 设计处理 |
| --- | --- | --- |
| 选择回答正确 | 本次识别正确 | 与独立输入分开统计；当前小程序不据此增强记忆调度 |
| 独立拼写、缺字输入 | 主动提取的一次证据 | 防止同日反复刷题产生虚高；具体更新规则查调度实现 |
| 自评没记住、困难、记住、太简单 | 学习者的反馈 | 可改变复习安排，保留自评来源 |
| 课堂观察 | 特定目标在课堂中的表现 | 记录独立、提示后、暂时不会，关联目标与学习场合 |
| 教师录音反馈 | 本次录音的观察 | 与整项任务确认、跨场合稳定掌握分别处理 |
| KET 练习评分 | 教师对该次练习各维度的判断 | 保留评分来源与维度，用于练习调整，不宣称官方认证成绩 |
| 课时、分钟与积分 | 提供的课程量或参与行为 | 与能力、保持率和练习正确率分开 |

设计新证据时，只收集判断实际需要的属性，通常涉及目标、来源、场合、时间、表现和提示方式。一次场合中的多个记录不能自动当作多次独立观察。

没有证据使用待观察、证据不足或空状态。展示层可以用灰色轨道表示未知，但不能将未知写成能力零分并参与平均。用户要求改展示时，明确它是否改变真实数据语义。

## 作业流转

默认过程：布置任务 → 学生练习与提交 → 教师检查 → 确认完成，或退回重做。

当前小程序同时维护提交状态、单条录音反馈与整项任务完成，不宜用一个布尔值替代全部含义。已提交待检查的工作从学生待处理数量中移出，由教师待办承接；教师退回后重新进入学生行动列表。文字任务的最终确认仍可由老师直接操作，不假设每项都有录音。

截止状态与处理状态分别保存。逾期提交保留时间事实，同时进入待检查；不要因为逾期就反复要求已提交的孩子重交。首页和任务页使用相同优先级与可处理数量。

修改任务内容时考虑版本，防止旧提交或旧页面确认新任务。仅改课程日期是否重置任务，读取目标项目的任务签名定义，不自行扩大影响。

## 动态与待办

动态记录“有新情况需要看”；待办记录“有问题需要处理”。动态可以标已读；待办依赖底层问题解除。教师打开录音页面不等于已经批改。

## 阶段与复习

阶段建议结合目标覆盖、不同课堂证据、独立表现及优先复习项。教师可结合课堂决定阶段，保留变更记录。当前页面的目标分组名称不必与晋级门槛一一等同，应检查服务端条件。

复习队列依据到期、预计保持率、困难和遗忘记录安排，再加入适量新内容。熟悉词降低频率，到期仍可复现。算法升级优先兼容旧历史并惰性迁移。

校准是比较预测和实际反馈。保留数据量、来源和观察窗口，先判断证据是否足够，再给调整建议。样本不足时继续观察；教师应用和恢复默认应可追溯。概率校准本身不能证明教学的因果效果。

## 激励与 AI

积分使用可核验活动，明确计分范围和去重方式。挑战角色单独标注，不混入真实学生记录。新增激励需要说明其促进的学习行为。

AI 先核实是否已接入。默认链路为提交练习 → 异步分析 → 教师复核 → 确认后展示；提交和人工检查不依赖分析成功。给出可追溯的原始证据位置和分析版本，避免把生成结果直接当作课堂事实。已有授权不需要重复请求；外部发送、部署和生产修改仍按本次范围处理。
